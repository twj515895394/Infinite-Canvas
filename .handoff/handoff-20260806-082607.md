## 1. 项目需求模板（一句话定位）

**Studio V2 个人版 MVP**：一个由全新 React UI 驱动的个人 AI 创作画布——复用现有 FastAPI 生成/画布能力，提供更好用的资产管理，并支持 Agent/Skill 管理与真实执行闭环。旧前端（`static/`）作为过渡期回退入口保留，新旧并行。

第一版四主线：
```
A. 新 React UI 与 React Flow 画布        （02/08/09 已完成）
B. 核心现有功能接入（图片/视频生成、ComfyUI、即梦、Codex Skill、上传/媒体、Provider/存储设置、Task Shelf、旧版回退）
C. 新资产库（Asset/AssetVersion/Tag/Collection + 回收站 + 画布拖放 + Agent 上下文）
D. Agent / Skill 管理与真实执行闭环（Runtime Probe、Skill 安装绑定、Agent Dock 任务、Artifact 保存）
```
明确延后：RunningHub 专项、Midjourney、独立对话页、提示词库管理。

## 5. 实施层决策点 / 已记录裁剪（含 F6 新增）

- **F6 Task Shelf 实时方案已定**：轮询（1.5s interval + 挂载时后端恢复），不引入 SSE/WS（MVP §7.2 允许）。
- **F6 生成任务契约（新）**：`/api/v2/generation-tasks`（POST 提交/GET 列表/GET {id} 查询/POST {id}/cancel）。状态机 `queued→running→succeeded|failed|cancelled`；即梦云端排队为 `jimeng_pending`，GET 时**惰性触发服务端自动续查**（`main.jimeng_query_result`+`jimeng_store_outputs`），轮询契约最终到终态。取消优先：`_update_task` 守卫，已取消任务不被后台协程改写。
- **Adapter 边界（F6 教训）**：v2 DTO → 旧 `OnlineImageRequest` 在 `run_generation_task` 内转换（旧函数访问 `reference_images` 等字段，直接传 v2 DTO 会 AttributeError）。
- **节点结果引用（§3.5 落地）**：成功时仅把稳定引用 `{urls, items}` 写回节点 `config.result`（随画布持久化）；任务详情/供应商字段/运行态一律不入画布（§14.3 投影不写回 Config）。供 F12 消费。
- **B5 已记录裁剪**（MVP §8.3）：无 Blob Store/物理去重/GC/Provenance 图谱；purge 硬引用仅扫画布节点。
- **F6 后端模块约定（新）**：`API/v2/generation_tasks.py` 用 `threading.Lock`（非 asyncio.Lock，跨 TestClient portal 线程与测试主线程）；任务保留上限 `TASKS_RETAIN_MAX=100`（裁剪最旧）；`AUTO_RUN` 测试开关（TestClient 的 portal 循环不保证调度后台任务，测试关掉后手动 `asyncio.run` 驱动状态机）；`queue_info` 供应商私有字段不透传视图（保留 `submit_id/kind/message`）。
- **React Flow 坑（F6 新发现）**：节点 prop 更新会清空 React Flow 内部选择 → `toRfNode` 必须回传 `selected`（来自 store selection），否则 Inspector 在参数修改后折叠。
- **Provider 探测数据源**：设置页已接 `/api/providers`、`/api/providers/test-connection`、`/api/storage-settings`；runtime-capabilities（CLI 探测 codex/gemini/jimeng）未聚合进设置页。

## 6. 环境与约定（重要，含新增）

- **Python 虚拟环境**：`.venv/`（Python 3.11.7）。所有 Python 测试/调试用 `.venv/Scripts/python.exe`（用户明确要求）。

- **前端**：`studio-v2/`，`npm run dev` → 5173（proxy `/api`→3888）；`npx vitest run`（node 环境，纯逻辑测试）；`npm run build`（tsc + vite）。Windows 下 hub 启动用 `cmd.exe /c npm.cmd ...`；vite 8 默认绑定 `[::1]`，readiness 探测 127.0.0.1 会超时（用 `netstat` 确认即可）。
